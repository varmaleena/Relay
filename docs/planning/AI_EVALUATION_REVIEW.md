## Architecture recommendation

Keep ADK as orchestration, with domain logic in ordinary typed Python packages. Models extract, classify, draft, translate, explain, and critique. Deterministic code selects packs, evaluates rules, computes deadlines/completeness, validates citations, authorizes actions, and changes state. LLM outputs never directly invoke delivery or institutional decisions. The API alone delivers an explicitly approved immutable packet version to authenticated mocks.

Use a shared model adapter supporting `fake`, `replay`, and `live`; record model ID, backend/location, prompt version/hash, schema version, parameters, token usage, elapsed time, retries, and trace ID. All result persistence must include the input revision/hash. Reject stale worker outputs after facts, pack, or packet revisions change. Recorded fixtures must remain labeled replay; invented fixtures cannot become measured results.

Separate domain schemas from transport aliases: camelCase JSON externally, consistent Python fields internally, explicit pack YAML mapping. Structured-output validation does not establish factual correctness. Constrain generated text to verified inputs and run deterministic checks plus entailment review. Bound total schema retries and repair loops globally; avoid multiplicative retries across SDK, workflow, queue, and adapter layers.

## Critical spec gaps to settle before implementation

1. **Streaming safety is the hardest unresolved design issue.** A regex applied to captions after raw model audio has played cannot enforce “output filter on every victim-visible text.” Preserve direct Live interaction only with an explicitly approved safety design: buffer audio until transcription can be checked (latency tradeoff), or use a constrained text-first utterance path. Put this experiment in M0/M5 acceptance; do not claim guarantees from prompts alone. Incoming audio can also contain volunteered secrets before transcription; prevent persistence of raw audio and scrub transcripts before durable writes.
2. **Secret-storage sequence conflicts.** Section 7.3 hashes/stores uploads before screening while 7.2 forbids storing credentials. Quarantine and validate before promoting objects to durable evidence, with immediate rejection/deletion and retention semantics. Regex is insufficient for screenshots/PDFs; document conservative handling and synthetic-only limitations.
3. **Workflow state is incomplete.** `NEEDS_HUMAN_REVIEW` is used by Verifier but absent from packet enums; add explicit review/blocked/failure states. Pipeline S2 and Pub/Sub claim `PLAN_READY` after packet verification, while the case state machine expects `PACKETS_VERIFIED`. Define distinct milestones/events. Packet repair means initial attempt plus at most two repair attempts, not ambiguous two total attempts.
4. **Missing-field acceptance conflicts.** UC3 requires three VERIFIED packets while bank requirements include fields absent from the supplied persona. Section 18 adds explicit `not_available` critical-field warnings; represent this as a typed missing/unknown/not-available value, never fabricated filler. Decide which fields are genuinely mandatory before selecting gold scenarios. Information requests and resends need approval bound to the new version.
5. **Schemas are not actually complete.** Classification lacks `clarifyingQuestion`; recipient schema lacks `recipientLanguage` and category mapping; deadline lacks business-calendar fields; completeness needs field weights/provenance; source draft evidence offsets are lost in 14.5; output of sentence-verdict verification differs from `VerificationCheck`. Add these before OpenAPI generation. `ReceiverBrief` suggests `reject_with_reason`, REST decision uses `reject`; centralize mapping.
6. **Rule grammar conflicts.** Earlier examples use `payment.method`, `authorization_type`, and `funds_likely_in_system`; §18 requires `facts.*`/`classification.*`. Normalize all packs or explicitly whitelist aliases. Reject arbitrary attributes, reflection, calls, literals of excessive size, deeply nested syntax, regex backtracking, and resource exhaustion. Make `exists` accept a safe path, not arbitrary object traversal. Missing facts should evaluate as unknown rather than silently excluding a needed institution.
7. **Deadline math needs a precise calendar contract.** Fixed-hour/day durations, months/years, daylight saving, and discovery/report start events have different meanings. Unsupported business calendars must remain visibly unsupported; never approximate legal deadlines. Reference clock injected into fixtures; the October 11 static example must not become “20 minutes ago” on October 13. Demo speed alters display/scenario clock only, not production legal time calculations.
8. **Pack publication is qualified, not absolute.** §4/14 explicitly allow accepted labeled unverified rules; §0/1 language suggests reviewed gating. Keep entry verification separate from pack publication status; record reviewer acceptance per rule/version with source checksum. Citation resolution only proves linkage, not entailment, current force, coverage, or official publisher identity. Preserve enactment/effective/retrieval dates, draft/final status, applicability, conflict, and amendment lineage.
9. **Global inference cannot be derived from data-at-rest region.** Record model processing backend/location separately and validate official controls. Source retrieval fallback index must preserve stable passage identity/hash. Retrieval cannot override published pack policy; it supports explanations and draft authoring.
10. **Source ingestion protects every hop.** Validate redirects and DNS again, block IPv4/IPv6 private/link-local/metadata addresses and DNS rebinding, apply decompression/page/token limits, disable HTML external assets, and never execute PDF active content. Official-domain allowlist does not prove an uploaded file is official or legally effective.
11. **No model can decide a real distress outcome.** Activate deterministic supportive fallback for both text and voice, prior to M5 text release. Use verified resources only; version and recheck them. Distress data is sensitive, so receiver sees only the minimal support flag.
12. **Cross-case linking is pseudonymous.** HMAC identifiers are linkable data, not anonymous; scope linking to approved org visibility, include tenant/key version in hash domains where appropriate, and delete derived links/clusters when a case is erased. Thresholds are heuristics, not statistical probability. Distinct shared types should not receive repeated weight for duplicate sightings.

## Evaluation design and credible claims

Start the 20-case harness at M2 and safety fixtures in M0/M1; M8 expands it rather than first creating it. Freeze gold independently of model output: reviewers author expected facts/rules; deterministic oracles compute recipients/order/deadlines against reviewed packs, with negative tests checking the oracle itself. Do not use the same model to generate gold, generate outputs, and adjudicate without human auditing. Keep held-out fourth-pack cases locked until pack authoring is complete.

Dataset v1 must contain at least 300 synthetic cases covering the three reference packs plus fourth held-out pack, English/Hindi/Hinglish evidence, all listed typologies/authorization types, noise/conflict/missing information, screenshots, a transcript subset, and at least 40 adversarial cases. “Balanced” across every Cartesian combination is impossible at 300; define a stratification matrix and report sparse slices honestly. True audio evaluation is P2, but live Hindi/English UC1 and first-spoken-reply latency are still P0 acceptance tests.

Run Relay, baseline, Rules, NoVerifier, and NoPack; §9 requires all three ablations despite an earlier singular diagram. Use at least three repeated runs when nondeterminism matters; aggregate at the case level so repeated samples do not inflate n. Use paired resampling across systems and clustering by case for repeated runs. Wilson intervals suit Bernoulli proportions; bootstrap case-level F1, completeness, order, cost/latency. For zero safety failures, show the nonzero upper confidence bound; never describe n=40 as proven safety. Declare undefined denominators instead of outputting 0 or 1.

Freeze baseline parsing/judge prompts; validate them on human-labeled outputs. The general baseline is defensible for guidance, but absence of structured packets is a product capability difference: mark packet metrics not applicable rather than pretending equivalent outputs. Add an optional strong pack-informed baseline if useful, clearly separate from the specified baseline. Compare randomized blinded pairs, including failures; do not cherry-pick. Targets (F1 .90, accuracy .90, recipient recall .95, completeness .95, citations 100%, zero observed forbidden outputs) stay aspirational until measured.

Track entity tuple F1; authorization confusion matrix; typology accuracy; recipient precision/recall; pairwise order/Kendall metric with tie policy; deadline duration/start event correctness; weighted completeness and field accuracy separately; sentence faithfulness; citation resolution and entailment separately; forbidden output and injection success; pack-item extraction/critic false acceptance; linking precision/recall; latency and cost. Include UI prevention/approval bypass tests as security evidence rather than only text metrics.

Each result must retain dataset version/hash, code SHA, pack versions/hashes, source snapshots, prompts, model/backend/parameters, mode, timestamp, per-case result/error/timeout, token counts, pricing source/date, n/CI, exclusions and sampling. Report failed/blocked cases and timeout rates; do not calculate latency only on successes without disclosure. For audio, measure utterance-end to first audible safe response; for plan/packets use facts-complete to ready. Token-only cost is model cost, not whole SaaS cost; state that boundary and include audio/other billable modalities where available.

A 20-case 3-percentage-point regression threshold is unstable (single accuracy error changes 5 points). Use it as a deterministic smoke safety gate and monitor paired failures; require larger scheduled live evaluations for statistical claims. CI schedule conflicts resolve to §15: fake/replay tests on PR, live smoke after dev deploy within token budget, full evaluation on controlled runs. Prompt changes bump version and rerun safety smoke.
